NAME

graphs.cfg - Configuration of the showgraph CGI

 

SYNOPSIS

$XYMONHOME/etc/graphs.cfg

 

DESCRIPTION

showgraph.cgi(1) uses the configuration file $XYMONHOME/etc/graphs.cfg to build graphs from the RRD files collected by Xymon.

 

FILE FORMAT

Each definition of a graph type begins with a "[SERVICE]" indicator, this is the name passed as the "service" parameter to showgraph.cgi(1). If the service name passed to showgraph.cgi is not found, it will attempt to match the service name to a graph via the TEST2RRD environment variable. So calling showgraph.cgi with "service=cpu" or "service=la" will end up producing the same graph.

A graph definition needs to have a TITLE and a YAXIS setting. (The X-axis is always time-based).

TITLE
text shown as the title of the graph.
YAXIS
text shown as the YAXIS heading.

If a fixed set of RRD files are used for the graph, you just write those in the RRDtool definitions. Note that Xymon keeps all RRD files for a host in a separate directory per host, so you need not worry about the hostname being part of the RRD filename.

For graphs that use multiple RRD files as input:

FNPATTERN
a filename pattern.
EXFNPATTERN
optionally, a pattern of files to exclude from the graph (see "[tcp]" for an example).

When FNPATTERN is used, you can use

"@RRDFN@"
in the RRDtool definitions to pick up each filename.
"@RRDIDX@"
is an index (starting at 0) for each file in the set.
"@RRDPARAM@"
contains the first word extracted from the pattern of files (see e.g. "[memory]" how this is used).
"@COLOR@"
picks a new color for each graph automatically.

Aggregate values across all files selected by FNPATTERN can be built with "@AVG:name@", "@SUM:name@", "@MIN:name@", "@MAX:name@", "@AVGNAN:name@", "@SUMNAN:name@", "@MINNAN:name@", "@MAXNAN:name@", "@COUNT:name@", "@MEDIAN:name@", "@STDEV:name@", "@PERCENT:name:pct@" and "@Ppct:name@" (short form, e.g. "@P95:name@" or "@P99.9:name@"). The "name" portion is the variable-name prefix used by preceding "DEF:name@RRDIDX@=..." lines - the aggregate expands to "name0,name1,...,nameN-1" followed by the operator's RPN. "pct" is a decimal percentile (0-100, at most one dot). For example, after defining "DEF:t@RRDIDX@=@RRDFN@:ds0:AVERAGE", the line "CDEF:avg=@AVG:t@" expands to "CDEF:avg=t0,t1,+,t2,+,3,/" when three files are matched; "@P95:t@" expands to the matching RRDtool PERCENT RPN; "@PERCENT:t:99.9@" is the long form of "@P99.9:t@".

When the graph is sliced by the "first"/"count" CGI parameters, the aggregates honour the slice: only the selected files contribute. An empty selection yields "UNKN" for arithmetic operators and "0" for "@COUNT:", so dividing a "@SUMNAN:" by a "@COUNT:" stays safe on the empty set (0/0 is UNKN in RRDtool RPN as well).

The operators follow rrdgraph_rpn(1). "@MEDIAN:" and "@STDEV:" skip UNKN values; "@MEDIAN:" averages the two middle values when N is even, and "@STDEV:" is the sample standard deviation (divides by N-1, so it is UNKN for a single value). "@AVG:" divides by the selected count, so one UNKN contributor makes the result UNKN - "@AVGNAN:" skips them. "@PERCENT:" does not skip UNKN values: it counts them as lower than any number. A percentile below 50/N returns the smallest value, and one above 100 gives UNKN.

Names accept alphanumerics and underscore (and the inner ":" in the "@PERCENT:name:pct@" form). The "@DSIDX@" tokens below must not appear inside an aggregate operand: they are not expanded there.

To draw the total of a dataset across all matched files, define the per-file DEF and sum it with "@SUMNAN:" (unknown values count as 0; use "@SUM:" if one silent contributor should make the total unknown instead). Give such an entry no split size: a graph paged by "first"/"count" would show partial sums. Example - one curve with the total read rate across all disks:

[diskio_ops_total]
        FNPATTERN ^diskio_ops\.(.+)\.rrd
        TITLE Total disk operations
        YAXIS Operations/sec
        DEF:t@RRDIDX@=@RRDFN@:reads:AVERAGE
        CDEF:rtotal=@SUMNAN:t@
        LINE2:rtotal#00CC00:total reads

Alternatively "@STACKIT@" stacks the per-file curves, whose silhouette is also the sum while keeping each file's contribution visible.

For a file that stores N samples of one measurement as N data sources (e.g. ping1..pingN), use the "DSCOUNT N" directive together with the "@DSIDX@" token. At parse time, every definition line containing "@DSIDX@" is expanded into N copies with "@DSIDX@" replaced by 1..N. The companion "@PREVDSIDX@" token expands to the current index minus one; a line that uses it loops over 2..N, so it never refers to a "ping0". To change the lower bound for one line, prefix it with "@DSSTART:K@": the prefix is removed and K becomes the lower bound. If DSCOUNT is omitted, the count is read from each matched RRD file when the graph is drawn, so hosts that store different numbers of samples each get every line.

Within such a file, "@DSMEDIAN:name@" expands to the RPN for the median of name1..nameN, where N is that file's count.

For a bundle viewed one service at a time (e.g. "tcp:conn"), FNPATTERN capture group 1 must be exactly the service component: showgraph uses it both as the legend (@RRDPARAM@) and to select the single service - see "[tcp]", where "^tcp.(.+).rrd" captures "conn" from tcp.conn.rrd.

The remainder of the lines in each definition are passed directly to the RRDtool rrd_graph() routine.

The following is an example of how the "la" (cpu) graph is defined. This is a simple definition that uses a single RRD-file, la.rrd:

[la]
        TITLE CPU Load
        YAXIS Load
        DEF:avg=la.rrd:la:AVERAGE
        CDEF:la=avg,100,/
        AREA:la#00CC00:CPU Load Average
        -u 1.0
        GPRINT:la:LAST: \: %5.1lf (cur)
        GPRINT:la:MAX: \: %5.1lf (max)
        GPRINT:la:MIN: \: %5.1lf (min)
        GPRINT:la:AVERAGE: \: %5.1lf (avg)\n

Here is an example of a graph that uses multiple RRD-files, determined automatically at run-time via the FNPATTERN setting. Note how it uses the @RRDIDX@ to define a unique RRD parameter per input-file, and the @COLOR@ and @RRDPARAM@ items to pick unique colors and a matching text for the graph legend:

[disk]
        FNPATTERN ^disk(.*).rrd
        TITLE Disk Utilization
        YAXIS % Full
        DEF:p@RRDIDX@=@RRDFN@:pct:AVERAGE
        LINE2:p@RRDIDX@#@COLOR@:@RRDPARAM@
        -u 100
        -l 0
        GPRINT:p@RRDIDX@:LAST: \: %5.1lf (cur)
        GPRINT:p@RRDIDX@:MAX: \: %5.1lf (max)
        GPRINT:p@RRDIDX@:MIN: \: %5.1lf (min)
        GPRINT:p@RRDIDX@:AVERAGE: \: %5.1lf (avg)\n

 

ADVANCED GRAPH TITLES

Normally the title of a graph is a static text defined in the graphs.cfg file. However, there may be situations where you want to use different titles for the same type of graph, e.g. if you are incorporating RRD files from MRTG into Xymon. In that case you can setup the TITLE definition so that it runs a custom script to determine the graph title. Like this:

	TITLE exec:/usr/local/bin/graphitle

The /usr/local/bin/graphtitle command is then called with the hostname, the graphtype, the period string, and all of the RRD files used as parameters. The script must generate one line of output, which is then used as the title of the graph. Each of the RRD pathname parameters will be enclosed in double quotes.

 

ENVIRONMENT

TEST2RRD
Maps service names to graph definitions.

 

NOTES

Most of the RRD graph definitions shipped with Xymon have been ported from the definitions in the larrd-grapher.cgi CGI from LARRD 0.43c.
